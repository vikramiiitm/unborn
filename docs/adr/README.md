# Architecture Decision Records (ADRs)

We track every significant technical decision here so the project stays coherent as it grows.

## Format

Each ADR is a markdown file: `docs/adr/XXXX-title.md`

### Template

```markdown
# ADR-XXXX: Title

## Status
Proposed | Accepted | Deprecated | Superseded by ADR-YYYY

## Date
YYYY-MM-DD

## Context
What is the issue or force that requires a decision?

## Decision
What did we choose?

## Consequences
Positive, negative, and neutral consequences.

## Alternatives Considered
What else did we look at and why was it rejected?
```

## Rules

- Any decision that affects architecture, tech stack, module boundaries, data model, or long-term optionality gets an ADR.
- ADRs are immutable once Accepted (we write a new one to supersede).
- Link ADRs from code, issues, and other docs when relevant.
- Keep them short and high-signal.
